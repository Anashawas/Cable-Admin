## 1. 🔴 Charger brands per station — multiple brands, each with a quantity

Today a charging point has a **single** charger brand
(`chargerBrandId` + the legacy `chargerBrand` text). We need a station to hold
**multiple charger brands, each with a count** — how many chargers of that brand
the station has.

**Example (one station):**

| Charger brand | Count |
|---|---|
| Benny   | 3 |
| Charger | 4 |
| …       | … |

### What we need
- **Data model:** a station owns a **list** of `{ chargerBrandId, count }`
  (replacing / alongside the single `chargerBrandId`).
- **Add / Update ChargingPoint** accept an array, e.g.:
  ```json
  {
    "chargerBrands": [
      { "chargerBrandId": 2, "count": 3 },
      { "chargerBrandId": 5, "count": 4 }
    ]
  }
  ```
- **GetChargingPointById** and **GetAllChargingPoints** return the same array
  (with the brand name resolved for display), e.g.:
  ```json
  "chargerBrands": [
    { "chargerBrandId": 2, "name": "Benny", "count": 3 },
    { "chargerBrandId": 5, "name": "Charger", "count": 4 }
  ]
  ```
- The admin UI will **multi-select** brands and set a **number** for each.

### Notes
- `count` is a positive integer (≥ 1); reject 0 / negatives.
- Keep the existing single `chargerBrandId` / `chargerBrand` **backward-compatible**
  during the mobile transition if easy (e.g. derive from the first brand), or tell
  us it's being replaced so we migrate the UI cleanly.
- The **total chargers** (existing `chargersCount`) — clarify whether it should
  now equal the **sum of the per-brand counts**, or stay independent.

## 2. 🔴 Confirm canonical role IDs + make `/api/users/summary` match them

**A real bug we hit:** the admin app uses **Admin = 2, User = 3, Provider = 4**
(`PROVIDER_ROLE_ID = 4`). The `GET /api/users/summary` example you sent showed
`roleId: 1` for Provider. If the live `summary.byRole` (and the paged
`GetAllUsers?roleId=` filter) actually use `1` for Provider, the admin's role tabs
show **wrong counts** and the Providers tab filters the wrong role.

**Please confirm the canonical role ids** and ensure **both**:
- `GET /api/users/summary` → `byRole[].roleId` uses the real ids (2 / 3 / 4), and
- `GET /api/users/GetAllUsers?roleId=` filters by those same ids.

(We've set the admin to send/read **2 = Admin, 3 = User, 4 = Provider** — tell us
if that's wrong.)
