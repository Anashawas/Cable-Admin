## 1. 🔴🔴 Car-type icon upload stores a URL that never serves the image

**Feature:** Car Database → brand logos (`UploadCarTypeIcon`).
**Symptom:** Uploading a brand logo **succeeds** (HTTP 200) and the brand's
`iconUrl` is populated, but **the image URL does not serve the file** — so logos
never render in the admin or the mobile app.

### What works
- `POST api/carmanagement/UploadCarTypeIcon/{id}` (multipart, field `file`) →
  **HTTP 200**, and `GetAllCarTypes` then returns e.g.
  `"iconUrl": "https://cable-app.com/CableCarTypes/<guid>.png"`.

### What's broken — the returned `iconUrl` is not retrievable
| Request to the returned `iconUrl` | Result |
|---|---|
| **No token** (what the app's `<img>` actually sends) | `401 Unauthorized` |
| **Valid Admin token** | `404 "File not found"` |
| Control: `GET api/carmanagement/GetAllCarTypes` (same token) | `200` ✅ |

So there are **two separate problems**, and **both** must be fixed:

**(a) The path requires authentication (401).**
The admin/app renders each icon with a plain `<img src={iconUrl}>`
(`src/features/system/components/CarDatabaseScreen.tsx`). A browser `<img>`
request **cannot attach a Bearer token**, so it always hits the anonymous case →
`401`. Car logos are not sensitive; this path must be **public / anonymous**.

**(b) The file isn't served even when authenticated (404 "File not found").**
Even with a valid Admin token the file 404s, which means the uploaded image is
**not actually retrievable** at the URL the API reports — either the file is not
being persisted to that location, or the `/CableCarTypes/` folder is **not wired
to static-file serving**.

### Repro (5 brands were uploaded during testing: Toyota 25, BMW 26, Volvo 76, Genesis 70, Avatr 77)
```bash
# 1) Upload succeeds and sets iconUrl
curl -X POST "https://cable-app.com/api/carmanagement/UploadCarTypeIcon/25" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" -F "file=@toyota.png"        # -> 200

# 2) The returned iconUrl does NOT serve the image
curl -i "https://cable-app.com/CableCarTypes/<guid>.png"                # -> 401 Unauthorized
curl -i "https://cable-app.com/CableCarTypes/<guid>.png" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"                              # -> 404 "File not found"
```

### What we need from BE
1. **Serve `/CableCarTypes/` as PUBLIC static files** (anonymous access, no auth) —
   e.g. `app.UseStaticFiles` mapped to the upload folder. `<img>` tags cannot
   authenticate, so an auth-gated logo path can never display.
2. **Confirm the file is physically written to that served folder** — a GET of the
   returned `iconUrl` currently returns `404 "File not found"` even with a valid
   token. Verify where `UploadCarTypeIcon` saves the file vs. the URL it reports.
3. Confirm the reported `iconUrl` **base/host and path casing** match the folder
   that is actually served.

### Impact / status
- Until (1) **and** (2) are fixed, uploading logos is a no-op — every `iconUrl`
  becomes a 401/404 dead link.
- The admin-side pipeline (source logos → transparent PNG → normalize → upload) is
  **built and verified**; ~62 brand logos are ready to bulk-upload in one pass the
  moment icon serving works. 5 test uploads are already on the brands above and
  will simply be refreshed.

---

## Priority
1. **#1 (a) — make `/CableCarTypes/` public** (unblocks `<img>` display).
2. **#1 (b) — ensure the uploaded file is actually served at the reported URL.**
